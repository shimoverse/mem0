Your project.
Remembered.

A small AI assistant that remembers a design project's audience, constraints, and decisions—so you can keep moving without repeating the brief.

Owner: ShilpiOne projectText onlyBuildathon prototype
The problem

“Every new AI conversation starts with me explaining the same project again.”

Important decisions get lost. Suggestions ignore constraints. Designers spend time repeating context.

The promise

“Tell it once. See what it remembers. Ask a better next question.”

Mem0 stores and retrieves project memories. An AI model uses relevant memories to write a helpful answer.

Who is this for? A solo product designer, like Shilpi, exploring one product idea over several conversations. First use case: onboarding for first-time freelancers.
02 / A small, clear first version

What we are building

Success means a new conversation can use saved project context—and the designer can see and remove that context.

FeatureWhat the designer can doWhat “done” looks like
Save project notesPaste a short brief and click “Remember this.”Show saving, success, or a clear retry message. Do not report success before memories are available.
See memoriesRead small cards with remembered facts.Cards show what was actually saved; they survive a page refresh in live mode.
Ask a questionAsk for a flow, idea, or writing suggestion.The answer uses relevant project memories and labels them “Context used.” This means supplied context, not proof of the AI's reasoning.
New conversationClear the question and answer while keeping project memories.Saved memories remain available for the next question.
Forget a memoryRemove an outdated or incorrect fact.Remove it from storage and future retrieval; refresh confirms it is gone. Clear the old answer to avoid displaying stale context.
Sample / live modeTry the experience before accounts are connected.Sample mode is clearly labeled. Live mode uses actual Mem0 memories and generated AI answers.

Keep for this prototype

One demo project. Short pasted notes. One question at a time. A memory panel. A fresh-conversation button. A forget action.

Save for a later version

Sign-in, team accounts, multiple projects, Figma connections, file uploads, voice, automatic research reports, and public launch.

Working assumption: this is a local, single-person demo using fictional project notes. Before inviting other users, add sign-in and separate each person's memories.

08 / No jargon needed

A small translation guide

PRD / prototype / MVP

A PRD is the plan for what a product should do. A prototype is an early version you can try. An MVP is the smallest useful working version. Here, the target is a small live prototype.

Codex / Mem0 / AI model

Codex helps write, change, and check your app's code. Mem0 stores and finds useful memories. An AI model generates the answer from your question and the context it receives.

API / API key / server

An API lets two services talk. An API key is your private access code. The server is the app's private service area, where those access codes and service calls belong.

Commit / push / publish

A commit saves a named snapshot of code. A push sends it to GitHub. Publishing makes the app available at a public web address. Those are separate steps.

What if Codex asks something technical?

Reply: “Explain the options in plain language. Recommend the simplest choice for this one-project prototype, tell me why, and continue when you have enough information.” If something fails, describe what you clicked and what you expected.
